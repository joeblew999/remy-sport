# GUI walk — what a phone shows, and what was fixed

Historical shared-workspace notes. Some referenced fixes and tests remain
uncommitted; this is not a statement of what the deployed application contains.
Paths marked `docs-check-ignore` below name those pending tests.

## Why

The GUI is getting better, and the way to keep it going is to look at it the
way a reader does: on a phone, in a real browser, screen by screen. A green
suite says a page works, not that it reads well. This is a log of that walk
on 2026-09-06, done with the Playwright MCP against `bun run dev`, phone
width first (390px, the size the screenshot walk uses) and desktop after.

## Rules

- Every finding is a box. It is ticked in the commit that fixes it, with what
  was done written beside it. A finding left alone says why.
- A fix that can be held by a test gets one, in the render tier, so the same
  screen cannot quietly go back.
- The product does not change beyond the finding: no new screens, no new
  data.

## Findings

### Before anything else: the browser was not showing the code

- [x] **A stale service worker served an old build over the dev server.**
      Every edit for an hour changed nothing on screen. The browser held a
      `/sw.js` registration from a build served on this origin months ago,
      made as a classic script; its worker answered every navigation from
      its precache. The browser refetches `/sw.js` on navigation to update,
      but the dev server answered with sw.ts as an ES module, which a classic
      registration cannot load, so the update failed silently every time.
      No console said so: the page's own code was the old build's. This is
      very likely why the GUI has felt hard to work on. Fix: in dev,
      `/sw.js` is a classic script that unregisters itself and reloads the
      tab (`legacyWorkerKillSwitch` in `src/web/vite.config.ts`); the next
      load comes from Vite. Held by `tests/e2e/dev-worker.spec.ts`, which <!-- docs-check-ignore -->
      registers the old worker the way a build does and watches the page end
      up on the dev worker — proven in WebKit, and by hand in Chromium. A
      browser already in the trap heals itself on its next visit to the dev
      server; nothing to clear by hand.

- [x] **After the first edit, the app ran twice.** Fast Refresh gives every
      module with a component a self-import by its bare URL, and once a dev
      session has seen an edit Vite serves the entry as `main.tsx?t=…`,
      which is a different module from `main.tsx`. So the entry ran twice:
      two React roots on one container, two query caches, two apps listening
      to the same hash. You signed in on the one you could see; the ghost
      still held the visitor's session and bounced you to the login screen
      from a page you were allowed on. Never on a fresh server, never in a
      build, always after the first edit — which is why it looked like the
      GUI, and not the tooling, was unreliable. Fix: the entry is excluded
      from Fast Refresh (it cannot hot-refresh anyway) in
      `src/web/vite.config.ts`; held by `tests/e2e/dev-entry.spec.ts`. <!-- docs-check-ignore -->

### Signed out, phone

- [x] **Live page: a game card is unreadable.** The team names wrap one word
      per line down a column about 100px wide ("Saint / Gabriel's / U16 Boys
      / vs / Bangkok / BC U16 / Boys") while the status badge sits alone on
      the right and the score below it. Cause: the live list reused the team
      schedule's grid, whose first column is a date. Fixed with its own grid
      (`.live-list` in styles.css): names and venue on the left, status and
      score on the right. Held by `tests/render/live.spec.ts`. <!-- docs-check-ignore -->
- [x] **Discover: the tab strip is cut off.** "All 4 · Live 1 · Upcoming 0 ·
      Past 3" does not fit 390px; "Past" is clipped at the right edge with
      its count hidden, and nothing shows that the strip scrolls. The
      province filters sat past the end of the chip row the same way. The
      strips still scroll (an earlier decision, and a test holds it); each
      now ends in a fade pinned to the right edge that says so. Held in
      `tests/render/mobile-layout.spec.ts`.
- [x] **Event page: "Recent results" was four bare lines in a box.** Two
      names and two scores stacked vertically, unreadable as results. The
      markup's class names had no CSS at all. Styled: names left, scores
      right, the winner's score in ink.
- [x] **Event page: "2026— Bangkok Round".** The title's dash lost its space
      in JSX. Fixed in `src/web/pages/event.tsx`.
- [x] **Organisations, signed out: every row says "Manage".** A visitor
      cannot manage anything. Now "Open", as on Teams; "Your organisations"
      keeps "Manage". Held in `tests/render/org.spec.ts`.
- [x] **Organisations: the row's second line is the slug.** "Bangkok ·
      assumption-college" shows an internal identifier in monospace. Now the
      kind of organisation, in the reader's language: "Bangkok · School". The
      organisation page's subtitle too.
- [x] **Team page: RECORD is a dash above five results.** The schedule below
      showed W and L beside every played game, so the dash read as broken.
      The record is those rows counted; a dash stays for a team that has not
      played. Held in `tests/render/team.spec.ts`.

### Signed in as a coach, phone

- [x] **Signing out leaves the coach's controls on the page.** On the team
      page as its head coach, "Team details" and "Manage squad" are offered.
      Press Sign out and stay on the page: both are still there, for a
      visitor, and would be refused on use. The reverse holds too: a page
      read before signing in keeps its visitor's answer after. Cause: sign-in
      and sign-out invalidate the session query and nothing else, so every
      `can` the server answered for the previous person stays in the cache.
      This is the ReBAC pain in one line — the screen and the server
      disagree about who is asking. Fix: `identityChanged` in
      `src/web/lib/session.tsx`, called by every sign-in and sign-out, drops
      every cached answer nobody is looking at and refetches everything on
      screen. An earlier agent had backed off exactly this over e2e
      flakiness; measured today, the tier is green twice over with it. Held
      by `tests/e2e/identity-cache.spec.ts`, which signs a fresh account in <!-- docs-check-ignore -->
      and out on a team page without a reload and watches Follow appear and
      go.
- [ ] **Editing `vite.config.ts` can crash the dev server.** Twice today a
      config edit produced two restarts at once — "Port 8787 is already in
      use", then `ERR_SERVER_ALREADY_LISTEN` — and the server died. A
      restart race between Vite and the Cloudflare plugin on a config
      change; ordinary edits are fine. Left alone: `bun run dev` again is
      the workaround, and the fix is upstream.
- [ ] **Profile says "who you are here" and shows nothing about who you
      are.** For a coach the page is one empty "Your players" box with a
      guardian's prompt. Left alone: what a profile should carry is a
      product question, not a rendering one.
